# Security model

Report a vulnerability privately to the repository maintainer using GitHub private vulnerability reporting when available. Do not include real session cookies, provider tokens, or private demos in public issues.

## Implemented controls

- The optional first-person routes follow the normal public/private instance policy. Each route admits one registry-pinned operator GLB by fixed size and fresh SHA-256 proof. Files are opened through no-follow local directory descriptors. Demo metadata cannot select a file path or supply viewmodel binaries.

- Argon2id password hashing. Passwords require 12–128 characters. No default password. First-admin enrollment requires a 256-bit operator code stored in a mode-0600 regular file, with only its hash in SQLite, exact Origin, rate limits and atomic one-use completion. Optional environment credentials only create the first administrator and never reset an existing account.
- Uninitialized instances gate account/provider/upload APIs. Guest uploads have an independent environment/admin policy, expiring hashed HttpOnly capability cookies, separate CSRF and IP limits, atomic count/storage limits and worker expiry cleanup. Guest principals cannot authenticate, acquire identities or appear as member accounts. Login never implicitly merges ownership.
- Random, server-side sessions with SHA-256 token digests in SQLite. HttpOnly, SameSite=Lax, Secure `__Host-` cookies in production for sessions and Steam state, preventing sibling-subdomain Domain cookie injection. Rotation on login and password changes; revocation on reset/logout. Private database/directory permissions.
- Authentication revalidates after asynchronous password work. Login rereads the immutable account and requires the same credential hash before issuing a session. Password changes atomically recheck the initiating session/CSRF and prior credential hash after verification/hashing, before replacing credentials and revoking sessions. Concurrent reset, logout or account changes cannot authorize a stale captured password mutation.
- Exact Host/Origin validation. CSRF tokens on authenticated unsafe requests. No permissive CORS. Restrictive CSP, clickjacking protection, MIME sniffing prevention, no-referrer policy, and HSTS on HTTPS.
- Per-user and temporary capability ownership checks; private-by-default demos; user-private notes; explicit public sharing; private-instance middleware covers playback and map assets.
- Atomic quota reservation, random storage paths, format signatures, bounded streaming uploads, capped decompression/output, bounded native parser processes, and retention.
- Persistent rate limits for authentication, registration, uploads, notes, and provider requests. Proxy IPs are trusted only when configured explicitly.
- Fixed-origin Steam assertion verification, exact signed return URL, state-cookie binding, one-use state and a persistent bounded nonce replay cache. Steam linking requires Origin and CSRF and revalidates the same session after assertion verification. Identities attach by immutable provider subject.
- Server-only provider credentials. Restricted authenticated upstream download URLs, public DNS checks pinned on the actual TLS request, HTTPS, no redirects, time/size bounds and bounded provider JSON. No general-purpose URL fetch endpoint.
- Steam history sync encrypts the member’s revocable game authentication code with AES-256-GCM under a key only the web service uses. `ENCRYPTION_KEY` supplies it. Without that variable, the service creates `encryption.key` with mode 0600 in the data directory, which protects a copied database but not a copied data directory. The service refuses to start when the key does not open all saved data, so keys are never mixed. The cursor, credentials and private demos are scoped to the member. Sync commits each match after revalidating the session and provider identity. A pre-identified upload associates an owner-selected file with an existing private match row.
- FACEIT imports and match-paired uploads require the linked subject in the authenticated match roster. Match-page caching is bounded and bound to the active member session and identity. Unlink and logout evict cached state. Downloaded filters read only from the member’s own demos. FACEIT mutations recheck the initiating session and current policy after provider I/O. Linking also rechecks the exact Steam subject before recording the FACEIT identity.
- Required per-job Linux Landlock/seccomp confinement inherited by native code. Read-only runtime libraries and isolated job files; no database, other demo, provider environment, network or subprocess access. Bounded artifact validation and quota checks before publication.
- Non-root Docker runtime, read-only root, capability drop, no-new-privileges and process/CPU/memory limits. Replay and offline speech workers have no network. The separate official-assets service has acquisition egress but receives no app database, demos, accounts or provider secrets; conversion subprocesses have their own required network/filesystem/process boundary.
- Isolated offline CPU transcription with read-only dedicated models, bounded Opus/utterance/output processing, lease-based publication and private caption access. Optional failure does not change primary demo readiness; retry requires ownership, Origin/CSRF and rate limits.
- Optional official-map acquisition prefers a unique approved historical source and otherwise permits a disclosed latest snapshot only for worker-observed official depot membership. Owner/guest empty-body requests require Origin/CSRF, persistent rates and bounded shared queue capacity. GET never enqueues or contacts Steam. Clients never choose source paths, URLs or manifest pins, and neither catalog matching nor latest selection proves the original map revision.
- Read-only equipment artwork endpoints use a fixed registry, private-instance access checks, descriptor-anchored filesystem reads and bounded PNG structure/CRC validation. The general map route excludes the equipment directory; no public SVG upload or conversion endpoint exists.
- Weekly CI image rebuild, dependency update PRs, production npm audit, and security boundary tests.

Parser failure metadata is bounded and classified before logging or presentation. Structured worker diagnostics retain the demo reference, stage, safe code and available exit/signal or whitelisted confinement reason. Raw native messages, arbitrary paths and environment values are excluded. This helps operators diagnose failures without treating native output as trusted text.

## Boundaries and remaining risks

This code has not had an independent security audit or penetration test. Do not describe it as proven secure solely because these controls and tests exist.

The native parser and model runtime remain substantial attack surfaces. Children are confined by Landlock ABI 3+ (Linux 6.2+ with Landlock enabled), plus seccomp restrictions for network, process escape/signals, metadata writes, ioctl, signal/lease-related fcntl operations, alternate syscall ABI and operations outside Landlock's filesystem mediation. The launcher fails closed on unsupported kernels or confinement errors. `PARSER_SANDBOX=off` is only for explicitly trusted local development; it restores shared-filesystem risk and must never process public uploads. Kernel/sandbox bugs remain possible; maintain both and prioritize native/parser/model-runtime updates. Separate per-job containers/cgroups may add defense for larger deployments.

Use a maintained HTTPS reverse proxy, disk monitoring/filesystem quotas, host patches, backups, and edge request limits. Keep the web listener private to the proxy. Multiple users behind a single untrusted proxy address share IP limits until trusted proxies are configured. IP limits alone do not stop distributed abuse; larger public deployments may need registration verification/CAPTCHA and an abuse process.

Application storage quotas and 500 ms bounded scratch polling are not hard filesystem quotas. A compromised child can grow files between polls; enforce host disk quotas. Job input copies, expanded files, originals, prepared output, database/WAL, and map assets need extra headroom. Container memory limits can kill the worker; interrupted jobs become failed and stale scratch is reclaimed. Monitor queue failures/restarts. Use one parser worker initially.

Account recovery is operator-assisted. Treat the operator, recovery-code handoff and reverse proxy as part of the account security boundary. See [account threat model and assurance evidence](docs/ACCOUNT-SECURITY.md). Shared demos contain player names/Steam IDs, positions and any extracted voice/chat/subtitles; publishing explicitly discloses this. Notes remain user-private. Revoking visibility prevents later downloads but cannot erase downloaded copies. No raw demo downloads are exposed.

Opus packets and speech outputs are untrusted. Parent schema/byte/time/identity validation bounds published artifacts; browser audio scheduling and decoder state are bounded. Bundled WASM requires CSP `wasm-unsafe-eval`; ordinary JavaScript `unsafe-eval` remains disabled. Chat/captions render as plain React text. Subtitles are model estimates, not verified statements. Runtime speech inference has no network and never sends recordings to a service. Install only trusted, dedicated operator-controlled model directories; never grant a general directory containing secrets or application data as a model root.

Gameplay sound is a separate optional recorded-evidence stream. Known native sound hashes and weapon-sound names resolve through a version-controlled registry, with bounded packed-position parsing. Unknown tokens stay silent. Recorded game events supply explicitly representative shots, objective and round samples, without synthesizing footsteps from movement or reloads from inventory. Cues are validated in bounded replay chunks, not an unbounded global footstep list. Audio overflow can drop optional cues with an explicit capability/truncation status while preserving primary replay events and state.

`/api/sound-assets` and its exact registry-owned WAV routes inherit setup/private-instance policy. Descriptor-anchored no-follow reads reject links, hardlinks and non-regular files. Discovery reads bounded metadata, while every payload request freshly verifies the declared hash and PCM structure. Two payload slots remain held through response completion or disconnect. Files are capped at 2 MiB, ten seconds, 48 kHz and two channels, with a 64 MiB bank ceiling. One universal Uint8Array/ArrayBuffer inspector enforces the same strict PCM format before backend delivery and browser decoding. It rejects allocation-hint objects, unsupported backing stores, compressed audio and contradictory headers. The browser also verifies payload hashes and bounds decoded caches and scheduled nodes. Gameplay and voice share a gesture-unlocked context and master control, with independent channels and seek/identity cancellation.

The isolated assets service prepares the fixed 116-sample native bank from official app `730`/depot `2347770`, using an explicit worker-observed manifest, verified package index and CRC-checked selected resources. This is idle work, separate from map readiness and replay parsing. S2V exports and offline MPEG-to-PCM normalization run in conversion-only stages under the required Landlock/seccomp helper, with downloader controls outside their writable roots. The pinned offline decoder validates complete MPEG frames and supported Xing/LAME metadata against independent byte/sample bounds before decoding. Only validated uncompressed PCM WAV is published or sent to the browser. Same-parent no-replace publication cannot replace an existing bank, and provenance stays outside public routes. There is no public sound upload, arbitrary source URL or online decoder fallback. Proprietary audio stays outside Git and container images.

The replay and speech workers remain network-isolated. Manual S2V use remains operator-only. The dedicated assets service can prepare approved historical sources or clearly disclosed latest official snapshots. Public requests never supply a source URL, map package, filesystem path, Steam account or converter arguments. Workshop/custom uploads are unsupported. Latest membership comes from the fixed official depot listing, never from an uploaded name alone. External model URLs remain excluded by policy and CSP.

`MAP_CATALOG_FILE` is operator approval, not a trust claim about an uploaded header. Its strict bounded entries bind the full known map/build/protocol/GUID/addon tuple to fixed app `730`, depot `2347770`, a uint64 manifest and verified map VPK SHA-256. Missing or ambiguous identity cannot establish a historical match. A fresh official inventory can instead authorize a disclosed latest source, while explicit addons and conflicting map evidence remain blocked. Distinct sources remain ambiguous even when their map VPK hashes match, because dependencies may differ. The recording fields are unsigned and cannot prove original geometry. Removing approval revokes that exact source and pack. It does not create a permanent map-name ban while the separate latest policy is enabled. Runtime catalogs are read-only to web and the asset worker; a separate one-shot operator command strictly validates and atomically installs supplied JSON. It does not discover versions or generate approval evidence.

The worker periodically lists metadata for fixed app `730`/depot `2347770` and the fixed direct-map path selector. Only validated bare names, one uint64 manifest, file SHA-1 and byte sizes enter a 128 KiB/256-map inventory. New selections require a check no older than 24 hours. Unknown names and caller-supplied source selectors cannot enqueue. The selected pin, size and SHA-1 are checked against the actual downloaded map before a SHA-256 content proof is persisted. Immutable latest queue IDs and content pack IDs are distinct. A stale validated inventory permits only previously published snapshot access, not a new source choice. Latest is explicitly not a historical-map assertion.

Read-only preparation diagnostics distinguish disabled policy, absent worker, missing/stale official inventory, optional catalog state and ineligible recording/ownership. Administrative details expose bounded status/count/version fields and the last inventory failure's fixed phase/code/timestamp/retry time, plus an optional bounded process exit code. Strict validation rejects arbitrary text and unknown fields; logs and heartbeats never retain native errors, paths, URLs or credentials. Successful inventory refresh clears the retained failure. Neither diagnostic GET nor build-info GET contacts Steam or enqueues conversion. The browser can poll bootstrap availability for at most 45 minutes, then submit one eligible immutable selection through the normal owner/guest Origin/CSRF/rate path. It never treats an absent worker as proof that historical approval is required, retries failed jobs automatically or substitutes manual geometry in automatic mode.

The asset service mounts only a bounded job volume, disposable source/tool cache, prepared assets and the approval catalog. Web sees prepared artwork read-only through `MAP_ASSETS_DIR`; this includes map models, agents, overviews, environments, equipment, gameplay sounds and landing previews. The assets image excludes the app database, original demos/replay data and provider environment. Do not mount a general data directory or secrets into it. Fixed-origin pinned tool/bootstrap acquisition and official Steam selectors are network-permitted; S2V and Node conversion subprocesses have network access denied.

Each conversion subprocess requires Linux x86-64, Landlock ABI 3+ and seccomp. Byte writes/truncation, creation, removal and rename are confined to the fresh map stage, including separate converter HOME/TMP. Downloader home, control files, manifest pins, cached executables, queues and published assets are outside that writable root. Seccomp denies network sockets, alternate syscall ABI, io_uring, process creation/escape, remote process/FD access, file links, FIFOs and device creation; native threads remain available. Metadata mutation (permissions, ownership, timestamps and xattrs), signals/limits targeting other processes, signal-routing fcntl operations and mutating filesystem ioctls are denied. Only bounded terminal/pipe queries and descriptor-local nonblocking configuration are allowed. Extra inherited descriptors are closed, and stdio cannot carry network sockets or writable regular files. The helper fails closed when confinement is unavailable. Container-scoped reads remain allowed, so the service must contain no unrelated data. This boundary is separate from, and does not weaken, the demo parser's existing stricter filesystem sandbox. The trusted acquisition supervisor still performs bounded Sharp image checks/normalization on approved official resources and converter output. Those in-process decoders are not covered by the subprocess sandbox. Their encoded/pixel/image-count bounds and the isolated container limit exposure, but this is not a universal native-decoder sandbox. Keep the asset image and its dependencies updated.

The optional idle landing-artwork task uses one fixed official Mirage screenshot resource at the observed manifest. Index SHA-1, native CRC and PNG hashes bind its source and output. Both its S2V decoder and Sharp normalizer run inside conversion-only children; acquisition controls and tool cache remain outside writable roots. Source/image bounds, a five-minute deadline, bounded attempts, per-write reservations and the shared Steam cooldown apply. A dedicated descriptor-anchored `--publish-preview` mode accepts only compiled shared registry names and same-parent `.preview-<6 alnum>` stages, using `RENAME_NOREPLACE`. Existing operator artwork is preserved. The task runs behind queued maps and ahead of the larger idle sound bank; failure changes neither map nor replay readiness. No proprietary screenshot is included in Git/images and there is no remote-image fallback.

One `flock` owner processes acquisition. Requests contain no demo IDs, owners or credentials, and bind an immutable approved source or official inventory selection plus a server-issued generation. At most 32 jobs are pending and 512 requests retained. Every scanner is capped at 1,024 entries. Only the single web process, before accepting HTTP, reclaims exact private single-link owned request temporary files left by an earlier web crash. The worker ignores recognized temporaries without deleting potentially live web writes. Unknown/operator files, symlinks and hardlinks are preserved. Jobs have a 45-minute deadline, 16 GiB cache/32 GiB prepared-asset budgets and periodic free-space guards preserving a 512 MiB reserve. Only exact worker-marked obsolete source caches or orphaned stages may be reclaimed. These checks supplement host quotas/cgroups rather than guaranteeing a hard storage/RSS ceiling.

A durable attempt ledger limits fresh conversions to three per generation across worker crashes. Recovery of an existing valid published pack consumes no new conversion attempt. After a 300-second cooldown, eligible transient failures allow an explicit owner retry under the same Origin/CSRF/rate/pending-capacity checks. The server renews the generation before clearing a terminal result. Failed safe removal preserves it. Latest retries retain verified source proof as processing state when necessary to recover an already-published content pack. Source mismatches and removed approvals stay terminal for that approval. There is no browser retry loop or automatic cancellation of a shared job when a viewer leaves.

Publication requires a complete validated pack with self-contained models, hash-bound texture plans, calibrated overview and environment. A descriptor-anchored, same-parent `renameat2(RENAME_NOREPLACE)` operation prevents overwriting an existing pack and avoids an empty-destination crash window. Ready publication requires a fresh source-policy check. Approved pack routes recheck unique catalog approval. Latest routes recheck their worker marker, immutable request/result source proof, ready status and official-name membership. Inventory refresh preserves the content identity of published snapshot URLs. Automatic mode serves the selected snapshot and manual packs carry the explicit `version-unverified` label. Approval revocation stops later requests but cannot recall downloaded copies. The optional landing preview uses fixed local names, bounded regular PNG/metadata, CRC/hash checks, fresh cache content proof and the same setup/private access policy.

Overview/environment metadata and PNGs use fixed same-origin paths, bounded descriptor-anchored reads, hash binding and instance access checks. Six-face environment packs must match both prepared model-tier manifests; equal square dimensions, individual/aggregate image bounds and a bounded serialized cache prevent concurrent unbounded allocation. The dedicated model routes cannot bypass those overview/environment checks. CSP permits browser-local blob fetches for embedded glTF textures while keeping network connections restricted to the same origin. The selective Steam installer uses fixed source/depot selections and pinned tools, either manually or behind the dedicated approved-source worker. Demo upload handlers cannot invoke it directly. Same-size asset rewrites can reuse filesystem timestamps. Raster caches therefore require fresh bounded content digests before reuse; stat identity alone never establishes content identity. Its periodic free-space guard and byte limits complement host disk quotas rather than replacing them.

Prepared map and CT/T model delivery uses fixed allowed paths and descriptor-anchored no-follow opens, rejects symlinked children, hardlinks and non-regular files, and bounds GLB sizes. Fresh content digests stream in 64 KiB blocks. Client disconnects cancel digest work and close descriptors before or after streaming ownership transfers. A generic static server must never expose the map directory.

The pinned Mirage lighting path requires the exact official map file hash and fixed CRC-checked textures. Read/decode caps apply independently to the EXR header, compressed chunk, decoded block and atlas sizes. The converter runs inside the existing stage boundary. Browser shader programs are bundled, with optional material bindings to local embedded textures and bounded dimensions. Replay smoke metadata is admitted under the ordinary replay ACL and shared journal/track limits. Its local worker applies bounded frames and grid sizes after manifest validation. Neither path takes a source URL, third-party shader program or executable replay input.

Equipment SVG conversion is also operator-only. Its source checks reject external resources, encoded references, CSS escapes, scripts, conflicting presentation declarations and symlinked files/ancestors before producing bounded PNGs; this is not a sandbox for arbitrary hostile artwork. Install trusted exports in the dedicated equipment directory. Proprietary game artwork is not committed or bundled, and the browser accepts only known same-origin raster paths from the equipment manifest.

Optional native muzzle evidence is extracted only from the fixed selected and CRC/hash-verified firearm resource through the existing required conversion boundary. Its generated metadata parser caps input bytes, block/array/token counts, nesting, strings and numeric tuples, rejects ambiguous bones/variants and never executes resource text. A fixed marker carries the supported local frame in the self-contained GLB. There is no new HTTP source selector, public conversion endpoint or arbitrary runtime asset URL. Existing operator banks are not replaced. Client firing cues use recorded immutable IDs/current weapons and absolute demo time, with independently owned procedural GPU resources.

GitHub scheduled rebuilds update base image packages but do not change pinned application dependencies without a lockfile update. Review/merge dependency PRs and redeploy both application and assets images. The normal Compose stack starts the assets service. Automatic map acquisition defaults off. Use `docker compose pull web worker assets` followed by `docker compose up -d web worker assets` to deploy the matching application and assets images. CI runs production npm audits and emits image SBOM/provenance. OCI labels record the full source revision and UTC build time, and the web exposes validated immutable build-file fields through `/api/config`; missing local identity remains unknown. Runtime configuration does not override that identity. CI checks a running container against its expected source, but build metadata alone is not proof of verification, an independent security audit or a guarantee of vulnerability absence.

Cold tool bootstrap and Steam listing have separate finite deadlines. Tools retain the existing 20-minute maximum; metadata receives 180 seconds after tool verification and the listing process remains capped at 120 seconds. Generic child cancellation preserves timeout versus operator abort without reflecting raw messages. Bootstrap HOME/CLI state and bundle extraction remain inside private disposable staging and are removed before tool publication. Fixed progress and bounded exit status expose no native output. The mandatory cold-image CI job receives no application mounts/secrets and downloads only fixed checksum-pinned tools. Its Steam metadata is original fixture data, never claimed official membership. Publication requires both normal verification and fresh-tool verification; both pass for the release below.
